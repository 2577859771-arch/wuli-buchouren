一、直接交给 WorkBuddy 的任务

请先阅读包内《交给WorkBuddy-部署任务.md》和《README-先读我.md》，部署完整版本的“物理不愁人”，交付一个能分享的正式 HTTPS 网址。首页、影片和实验应能在手机普通网络下访问，不需要 VPN 或 ChatGPT 账号。

优先沿用现有 WorkBuddy 项目或已授权的托管服务。不要把 localhost、局域网 IP 或不稳定的临时隧道当作最终交付。若需要登录、实名、账户授权、付费或更换主机，请明确说明需要用户完成的步骤；不要擅自购买、删除旧站或覆盖用户数据。

大陆网络能否打开，必须在真实手机网络中验证；不能仅凭平台名称或网址格式保证。

二、这些功能必须保留

  • 电影感首页、4 部已上传影片、一个可自由切换的播放器；不再显示预留空位或“即将上线”卡片。
  • 42 个物理专题、126 个基础知识条目、配图、公式、推导、搜索、收藏和高中／大学模式。
  • 18 项 3D 实验：physics-lab 文件夹和 lib/ 整体保留，不能拆散相对路径。
  • 12 类题目参数驱动的三维实验，保留参数校验与适用条件；不要声称任意题目都能生成精确 3D 模型。
  • 8 个大学数学模块、导数／积分交互工具、14 个专题的 28 段教材补充及资料来源书目。
  • 文字／图片上传解题、千问服务端接口、题干核对、失败时保留题目、本站邮箱账号注册／登录。

三、部署步骤

  1. 先备份原站及数据库。此项目有后端和数据库，不是只上传 index.html 就能工作的纯静态站。
  2. 采用支持 node:sqlite 的 Node 22 环境，按锁文件安装依赖，执行 npm run build，使用 node scripts/serve.mjs 启动。包内也提供 Dockerfile。
  3. 设置 HOST=0.0.0.0、平台提供的 PORT 和真实 HTTPS PUBLIC_ORIGIN。数据库默认位于 data/physics.sqlite，必须使用持久存储和备份。
  4. 如改用其他后端或数据库，适配 worker/ 的 API 与数据库语义。已有用户／会话时不要盲目重新建表，也不要用空库覆盖旧库。
  5. 千问 API Key 只配置在服务端秘密变量中，不写入前端、仓库或公开文件。新主机没有密钥时，通过秘密变量入口配置；模型名称与识图能力以供应商账号实际权限为准。
  6. 关闭生产环境设计预览模式，页面与账号／AI API 尽量同源，正确保护 Cookie、CSRF 和调用配额。邮件验证／密码找回需要真实发件服务，未配置时不能声称邮件已发出。
  7. 上传完整 public/，特别是 public/media/。媒体服务须正确支持 MP4、HEAD 和 Range／206；保留音轨、拖动及全屏，避免同时预加载全部影片。
  8. 保留本地字体、KaTeX、Three.js 和 Rapier WASM，检查相对路径、MIME 及资源安全策略，不要改回必须访问外部 CDN 才能工作的形式。

四、上线后必须验收

  • 运行 npm run build 和 npm test（当前 16 组自动测试），如实标注未运行的检查。
  • 使用真实手机分别测试普通 Wi-Fi、移动网络及微信内置浏览器；未取得相应设备／网络时，明确标注未验证。
  • 首页无需 ChatGPT 账号；只有 4 张真实影片卡片；播放、切换、拖动正常，数学公式和交互工具正常。
  • 18 项 3D 实验能加载和操作；资料来源包含新增教材；文字题、图片题以及适用题目的 3D 参数正常。
  • 本站邮箱账号与会话正常；未配置邮件服务时提示准确；重新部署后用户数据库仍保留。

最终请回复：真实 HTTPS 网站链接、部署平台、手机网络实测结果、尚未配置的功能，以及用户必须完成的最少步骤。
